I wanted to get you the full rundown on yesterday while it's fresh. The short version: the site went down around 10 AM your time, and the reason it went down turned out to be the same reason we ended up spending the whole day on it. Someone had gotten into the site again.

What happened

An attacker added code to the site's theme and also dropped a hidden plugin into a folder WordPress loads automatically. Their theme edit had a typo in it, which is what crashed the site. Honestly, that typo did us a favor. The hidden plugin was working fine and would have kept running quietly.

That hidden plugin did two things. It loaded a script on every page that tries to trick visitors with a fake "verify you are human" box and copies a malicious command to their clipboard (this is a known scam kit, and it also grabs browser cookies). And it had a secret login link that let the attacker sign in as an administrator without a password. That script was live on the site for about three hours yesterday morning, from roughly 8 AM to 11:50 AM your time.

We also found leftovers from the July incident that the last cleanup missed: an attacker admin account named "adminuser" from July 29, traces of a file manager plugin they installed to upload their tools, and a robots.txt they had rewritten. The July account had opened the admin screen for the coupon book sign-up form, which holds about 16,000 entries. We found no sign that anything was exported, but I want you to have that fact rather than not.

What we did

✅ Removed the malicious code from the theme and deleted the hidden plugin. The site was back up at 10:52 AM your time and clean by 11:50 AM.
✅ Deleted the attacker's leftover account data, the file manager remnants, and the rewritten robots.txt.
✅ Invalidated every password on the site and rotated the site's security keys, which logged out every browser everywhere.
✅ Pointed the site's admin email at us instead of the previous developer's inbox (that inbox was still getting every security notice from WordPress, including a recovery link yesterday).
✅ Turned on the Wordfence firewall (it had been sitting in "learning mode" and blocking nothing), enabled the plugin and theme file scans that were switched off, and ran a full scan with everything on. It came back clean.
✅ Removed 13 plugins the site wasn't using, including two that had been abandoned by their authors, and cleared out the leftovers of the file manager tool the attacker had installed in July. Two small pieces of functionality moved into your theme's own code so they no longer depend on outside plugins. The site went from 31 installed plugins to 19.
✅ Wrote up every change with timestamps so we have a full record.
